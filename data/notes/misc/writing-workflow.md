# How I actually write these notes

Meta, but useful, since the whole project is about searching them.

One file per idea, not one per lecture. A lecture file becomes a dumping ground and by
March I cannot find anything in it. If a note grows past a screen and a half it wants
splitting, and the split is usually obvious because there are two H2 sections that never
refer to each other.

Filenames in lowercase with hyphens, folder per broad area. The folder is a weak signal
and I do not agonise over it; things that could go in two places go in either.

Front matter only when I have a reason. Tags earn their place when I know I will want to
pull a set together later, otherwise they are ceremony. This inconsistency is honest and
it is also the reason the search tool cannot rely on tags being present, which is worth a
line in the report.

Write in my own words before quoting the source. If I cannot restate it, I did not follow
it, and copying the slide only hides that from myself until the exam.

Leave a TODO where I know something is unresolved, in capitals, on its own line, so a grep
finds them all. Currently eleven of them across the vault, which is about ten more than I
would like.

Dates in ISO order, so 2026-02-11, because they sort.

The failure mode this all exists to fix: I remember writing something about why the same
number of dimensions costs different amounts at different collection sizes, but I cannot
remember whether I filed it under embeddings or infrastructure, and I definitely do not
remember which words I used. Folder browsing does not help. Grep does not help unless I
guess the exact phrase. That gap is the entire motivation for the project and I should put
this paragraph in the introduction almost verbatim.
